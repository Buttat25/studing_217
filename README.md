## Установка
Нужны Python 3.10+ и git.
```bash
python -m venv .venv
```
Активируйте окружение — Windows: `.venv\Scripts\activate`, macOS/Linux: `source .venv/bin/activate`.
```bash
python -m pip install -r requirements.txt
```

## Как устроена задача
```
tasks/tNN_name/
├── README.md        ← условие, формат ввода и вывода программы, договорённости, пример, git-сценарий
└── tests/           ← готовые тесты (не изменяйте их)
```
**Программу вы пишете сами с нуля:** создайте в папке задачи файл, указанный в разделе «Программа»
README (например, `tasks/t01_trains/trains.py`). Как устроить код внутри — функции, классы,
модули — решаете вы.

**Тесты уже написаны** — свои писать не нужно. Тесты не вызывают ваши функции: они **запускают
программу** так же, как вы из командной строки (`python trains.py schedule.txt`), подают ей ввод
(файл, аргументы, строки на стандартный ввод) и сравнивают то, что она напечатала, с ожидаемым —
строка в строку (пробелы в конце строк не важны). Поэтому формат вывода из README нужно соблюдать
точно. Ошибки во входных данных программа сообщает так, как сказано в README (строка `Ошибка: …`
или `ОШИБКА: …`), формулировку после двоеточия выбираете вы. Если программа падает с трассировкой
(Traceback), тест не пройден — даже там, где ожидалась ошибка.

Открытые тесты в `tests/` — часть контрольных: преподаватель дополнительно проверяет решение полным
набором, в котором есть случаи, которых нет в открытых. Внимательно читайте договорённости в README.

## Самопроверка
```bash
python tools/check.py 1
```
```bash
python tools/check.py all
```
`-v` — подробности: какие тесты упали, что ожидалось и что напечатала ваша программа.

Результат выводится по категориям тест-кейсов:
<!-- пример отчёта: начало -->
```
Задача 1:
- Типичные: 14/14 ✓
- Наивные: 11/11 ✓
- Краевые: 18/18 ✓
- Формат: 41/41 ✓
- Фаззинг: 9/9 ✓
Итого: 93/93
```
<!-- пример отчёта: конец -->
Числа — количество наборов данных: у одного тест-кейса их обычно несколько.

## Сдача
```bash
python tools/check.py submit --name "Фамилия Имя"
```
Команда проверит все задачи и создаст архив `submissions/submission_<имя>_<дата>.zip` с вашими
решениями и отчётом по категориям (он же — рядом в файле `.txt`). Архив отправляется
преподавателю вместе с основным отчётом.

## Git-сценарии
У каждой задачи есть git-сценарий (описан в конце README задачи). Все они выполняются в этом же
репозитории, и проверяются автоматически по веткам и тегам. Общая история в `main` у всех одна,
переписывать её нельзя. Каждый студент:
- работает только в **собственных ветках** с логином в начале: `<логин>/main` (ваша главная ветка,
  от `main`), `<логин>/t01-solution`, `<логин>/develop`, `<логин>/t05`, `<логин>/t06` и т. д.;
- помечает результат **собственными тегами**: `<логин>-t05-bug`, `<логин>-v1.0.0` и т. д.;
- отправляет ветки и теги в репозиторий, который укажет преподаватель (`git push origin <ветка> <теги>`).

`<логин>` — ваша фамилия латиницей в нижнем регистре, например `ivanov`. Ветки и теги чужих логинов
не трогайте. Задачи 5 и 6 выполняются на учебных программах из папки `git_practice/`:
- `git_practice/t05_grades/` — «Сводка оценок», поиск ошибки через `git bisect` и откат через `git revert`;
- `git_practice/t06_library/` — «Библиотека», поиск виновного коммита через `git blame` и исправление ошибок.
