# Задача 1. Расписание поездов

На станции есть несколько платформ. Известно время прибытия и отправления каждого поезда.
Найдите минимальное количество платформ, чтобы ни один поезд не ждал освобождения места.

## Программа
Создайте в папке задачи программу `trains.py` (имя может быть другим - см. README курса).

**Запуск:** `python trains.py schedule.txt` или `python trains.py < schedule.txt` (без аргумента
расписание читается из стандартного ввода). Файл - в UTF-8.

**Ввод** - по строке на поезд:
```
Поезд 1: прибытие 09:00, отправление 09:30
```
- Название - всё до двоеточия (без пробелов по краям).
- Слова «прибытие» и «отправление» - в любом регистре, лишние пробелы вокруг `:` и `,` допустимы.
- Время - `ЧЧ:ММ`, часы можно писать одной цифрой (`9:05`).
- Пустые строки и строки, начинающиеся с `#`, пропускаются.

**Вывод** - минимальное количество платформ, пустая строка и распределение поездов по платформам
(см. пример):
- время печатается как `ЧЧ:ММ` (`9:05` → `09:05`), отправление - как задано (`24:00`, `00:30`);
  между временами - символ `–` (U+2013, а не дефис); поезда на платформе - в порядке прибытия,
  через `, `;
- для пустого расписания - только строка `Минимальное количество платформ: 0`.

## Условия
- Поезд занимает платформу на **полуинтервале** `[прибытие, отправление)`: поезд, прибывший
  ровно в момент отправления другого, может встать на его платформу.
- Поезд стоит на платформе **не больше 2 часов** (ровно 2 часа - можно).
- `24:00` - допустимое время отправления (конец суток), но не прибытия.
- Отправление раньше прибытия - поезд уходит на **следующие сутки**: `23:30–00:30` - час через
  полночь.
- Распределение: поезда по порядку прибытия (при равном прибытии - в порядке ввода), каждый -
  на свободную платформу с наименьшим номером, если свободных нет - на новую.
- 10 000 поездов обрабатываются меньше чем за секунду.

## Пример
Ввод:
```
Поезд 1: прибытие 09:00, отправление 09:30
Поезд 2: прибытие 09:10, отправление 10:00
Поезд 3: прибытие 09:30, отправление 10:30
Поезд 4: прибытие 10:30, отправление 11:00
Поезд 5: прибытие 10:40, отправление 11:30
```
Вывод:
```
Минимальное количество платформ: 2

Распределение по платформам:
  Платформа 1: Поезд 1 (09:00–09:30), Поезд 3 (09:30–10:30), Поезд 4 (10:30–11:00)
  Платформа 2: Поезд 2 (09:10–10:00), Поезд 5 (10:40–11:30)
```

## Git-сценарий (базовые ветки)
Всё делается в общем репозитории курса, в ваших ветках и тегах: вместо `<логин>` - ваш логин в edu.susu.
Ваша «главная» ветка - `<логин>/main`; если её ещё нет, создайте от `main`: `git switch -c <логин>/main main`.
Ветки и теги отправляйте в репозиторий: `git push origin <ветка> <тег>…`. Не удаляйте ветки, которые нужны для проверки.

1. Создайте ветку для решения от своей главной: `git switch -c <логин>/t01-solution <логин>/main`.
2. Напишите решение - **не меньше двух** осмысленных коммитов, которые меняют только
   `tasks/t01_trains/` (сообщения вроде «feat(t01): разбор расписания», а не «fix»).
3. Слейте ветку в `<логин>/main` так, чтобы в истории остался коммит слияния: Pull Request на GitHub
   или `git switch <логин>/main` и `git merge --no-ff <логин>/t01-solution`.
4. Отправьте обе ветки: `git push origin <логин>/main <логин>/t01-solution`.

Что проверяется: ветка `<логин>/t01-solution` есть и влита в `<логин>/main` коммитом слияния;
в ней не меньше двух коммитов, и они меняют только папку задачи; в `<логин>/main` есть `trains.py`.
