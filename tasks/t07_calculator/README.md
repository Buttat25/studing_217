# Задача 7. Калькулятор в командной строке

Калькулятор принимает математические выражения и выдаёт результат. Внутри - проверка деления на
ноль, логарифма от отрицательного числа, настройка точности. Дополнительно: конвертер величин,
матричный калькулятор (сложение, умножение матриц) и логический калькулятор (И, ИЛИ, НЕ).

## Программа
Создайте в папке задачи программу `calculator.py` (имя может быть другим - см. README курса) - её запускают тесты, они проверяют ввод и вывод.

**Требования к коду (проверяются автоматически по исходникам, `check.py` покажет нарушения):**
решение состоит из модулей `calc_math.py` (выражения и числа), `calc_convert.py` (конвертер),
`calc_matrix.py` (матрицы), `calc_logic.py` (логика) и программы (`calculator.py` или с другим именем), которая их связывает.
Первые четыре модуля **не импортируют друг друга**. Нарушение - минус баллы за задачу.
`eval`/`exec` запрещены: выражение приходит от пользователя.

**Запуск:**
- `python calculator.py` - читает строки из стандартного ввода до конца ввода или до `exit`/`quit`
  (в любом регистре) и на каждую печатает ответ; пустые строки пропускаются. Кроме ответов,
  ничего не печатается (никаких приглашений вроде `> `).
- `python calculator.py "2 + 2"` - вычислить одну строку (аргументы склеиваются через пробел),
  напечатать ответ; код возврата 1, если ответ - ошибка, иначе 0.

**Ответы:**

| Ввод | Ответ |
|---|---|
| выражение: `2 + 2 * 2` | `= 6` |
| значения переменных после «где»: `x * 2, где x=5` | `= 10` |
| логическое выражение (есть `AND`/`OR`/`NOT`/`true`/`false` или сравнение): `true AND x > 5, где x=7` | `= true` / `= false` |
| `convert 5 km to miles` (или `in`) | `= 3.10686 miles` - единица печатается, как её ввели |
| `matrix A + B`, `matrix A - B`, `matrix A * B`, `matrix A * 3`, `matrix det A`, `matrix transpose A` (или `t`) | `= [[6, 8],` и на следующей строке `   [10, 12]]` - строки матрицы выровнены под первой |
| `precision 5` | `Точность установлена: 5 знаков после запятой` (`1 знак`, `2 знака`, `11 знаков`) |
| `precision` | `Текущая точность: 10 знаков после запятой` |
| `history` | строки `  1. 2 + 2 * 2 = 6` и `  2. 10 / 0 → ОШИБКА`; пустая - `История пуста` |
| `save ФАЙЛ` | `История сохранена: ФАЙЛ`; в файле строки `1. 2 + 2 * 2 = 6` без отступа |
| `help` | список команд, первая строка - `Команды:` |
| любая ошибка | `ОШИБКА: <описание>` - программа не падает и продолжает работу |

Слова `convert`, `matrix`, `precision`, `history`, `help`, `где`, `AND`, `OR`, `NOT`, `true`, `false`
и единицы измерения - в любом регистре; имена функций и переменных - как написаны. В историю
попадают только вычисления (выражения, логика, convert, matrix); матрица записывается в одну строку:
`[[6, 8], [10, 12]]`.

## Договорённости
**Выражения.** Операции `+ - * / ^` (или `**`), скобки, унарные минус и плюс. `^` сильнее унарного
минуса и правоассоциативна: `-2^2 = -4`, `2^3^2 = 512`, `2^-1 = 0.5`; `* /` сильнее `+ -`; одинаковые
операции - слева направо. Числа: `12`, `3.5`, `.5`, `5.`, `1e3`, `2.5E-3` (только цифры 0–9).
Функции `sqrt`, `ln`, `log(x)` (десятичный), `log(x, основание)`, `abs`, `sin`, `cos`, `tan`, `exp`;
константы `pi`, `e` (переменная с тем же именем важнее). У `sin`, `cos`, `tan` результат меньше
1e-12 по модулю считается нулём: `sin(pi) = 0.0`.
- Целые считаются точно (`10^100` - все 101 цифра), но по модулю должны быть меньше 10^1000;
  деление `/` всегда даёт дробное число (`10 / 2 = 5.0`).

**Вывод чисел.** Целое - как есть, все цифры. Дробное - округление до `precision` знаков после
запятой (по умолчанию 10, допустимо 0–15) «как в школе» (половина - от нуля) по десятичной записи
числа: `2.675 → 2.68`; лишние нули убираются, но один знак после точки остаётся (`13.0`, `0.3`);
ноль (и `-0.0`, и то, что округлилось до нуля) - `0.0`. Если |x| ≥ 1e15 или 0 < |x| < 1e-6 -
экспоненциальная запись: мантисса с `precision` знаками без лишних нулей: `1e+20`, `1.5e-12`,
`1.2345678901e+17`.

**Конвертер.** Единицы: длина `m`, `km`, `cm`, `mm`, `mi` (`mile`, `miles`), `ft` (`foot`, `feet`),
`in` (`inch`, `inches`), `yd` (`yard`, `yards`); масса `kg`, `g`, `mg`, `t` (`ton`, `tonne`, `tonnes`),
`lb` (`lbs`, `pound`, `pounds`), `oz` (`ounce`, `ounces`); время `s` (`sec`), `min`, `h` (`hr`, `hour`,
`hours`), `day` (`days`); температура `C` (`°C`, `celsius`), `F` (`°F`, `fahrenheit`), `K` (`kelvin`).
Точные множители: 1 mi = 1609.344 m, 1 ft = 0.3048 m, 1 in = 0.0254 m, 1 yd = 0.9144 m,
1 lb = 0.45359237 kg, 1 oz = 0.028349523125 kg. Результат - не больше **6 значащих цифр**
(половина - от нуля), без лишних нулей и точки: `3.10686`, `1000`, `123457000`, `0`; при |x| ≥ 1e15
или |x| < 1e-6 - `1e-9`, `2.5e+20`.

**Матрицы** - в формате `[[1, 2], [3, 4]]` (числа целые и дробные, со знаком, `1e3`). Матрица 1×1 -
матрица, а не число. Матрицу можно умножить на число (в любом порядке: `matrix 2 * A`,
`matrix A * 2`); целые остаются целыми. Определитель считается точно (у целых - целое).
Элементы печатаются как числа калькулятора, но всегда в обычной записи
(`0.5`, `2.0`, `0.0`).

**Логика.** Сравнения чисел `< <= > >= == !=`; `true`/`false` сравниваются через `==` и `!=`.
Приоритет (от слабого к сильному): `OR` → `AND` → `NOT` → сравнения, поэтому `NOT x > 5` - это
`NOT (x > 5)`. Значения задаются после «где» для **всех** переменных выражения (`true`/`false`
или число).

## Пример
Строки с `> ` - ввод (сама программа их не печатает), остальные - ответы:
```
> 2 + 2 * 2
= 6
> 10 / 0
ОШИБКА: деление на ноль
> log(-5)
ОШИБКА: логарифм определён только для положительных чисел
> sqrt(16) + 3^2
= 13.0
> convert 5 km to miles
= 3.10686 miles
> convert 100 kg to lbs
= 220.462 lbs
> matrix [[1, 2], [3, 4]] + [[5, 6], [7, 8]]
= [[6, 8],
   [10, 12]]
> matrix [[1, 2, 3]] * [[1], [2]]
ОШИБКА: несовместимые размеры матриц (1×3 и 2×1)
> true AND (false OR true)
= true
> NOT (x > 5) AND (y < 10), где x=7, y=3
= false
> precision 5
Точность установлена: 5 знаков после запятой
> 1 / 3
= 0.33333
> history
  1. 2 + 2 * 2 = 6
  2. 10 / 0 → ОШИБКА
  ...
```
Текст после `ОШИБКА:` - на ваше усмотрение (кроме размеров матриц), но он должен объяснять, что не так.

## Git-сценарий (релизные ветки и теги)
Всё делается в общем репозитории курса, в ваших ветках и тегах: вместо `<логин>` - ваш логин в edu.susu.
Ваша «главная» ветка - `<логин>/main`; если её ещё нет, создайте от `main`: `git switch -c <логин>/main main`.
Ветки и теги отправляйте в репозиторий: `git push origin <ветка> <тег>…`. Не удаляйте ветки, которые нужны для проверки.

1. Когда программа готова, в `<логин>/main` поставьте тег первого релиза: `git tag <логин>-v1.0.0`.
2. Заказчик просит доработку: начните её в ветке `<логин>/t07-feature` от `<логин>/main` (хотя бы
   один коммит; доделывать к сдаче не обязательно).
3. Параллельно нужно срочное исправление текущей версии: создайте ветку **от тега** -
   `git switch -c <логин>/hotfix-1.0.1 <логин>-v1.0.0`, исправьте, закоммитьте и поставьте тег
   `<логин>-v1.0.1` на коммит исправления.
4. Влейте исправление в `<логин>/main` (`git merge --no-ff <логин>/hotfix-1.0.1`). Работа над новой
   функцией должна остаться в своей ветке и не попасть в релиз 1.0.1.
5. Отправьте ветки и теги: `git push origin <логин>/main <логин>/t07-feature <логин>/hotfix-1.0.1 <логин>-v1.0.0 <логин>-v1.0.1`.

Что проверяется: тег v1.0.0 - в `<логин>/main`; ветка hotfix создана от v1.0.0 и содержит исправление;
тег v1.0.1 стоит на нём и влит в `<логин>/main`; ветка новой функции сохранена, и её коммиты не попали
в v1.0.1.
