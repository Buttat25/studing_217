# Задача 4. Симулятор очереди в магазине

Программа моделирует работу магазина: покупатели приходят, встают в очередь, обслуживаются
кассирами. Посчитайте статистику: среднее время ожидания, максимальную длину очереди,
сколько покупателей не дождались и ушли.

## Программа
Создайте в папке задачи программу `queue_sim.py` (имя может быть другим - см. README курса). Два режима:

**1. Покупатели из стандартного ввода:**
`python queue_sim.py [--cashiers N] [--max-queue N|none] [--close T] < customers.txt`

По строке на покупателя: `приход обслуживание` - два числа в минутах через пробелы (можно дробные:
`2.5`, `.5`, `1e1`). Пустые строки и строки с `#` в начале пропускаются; порядок строк любой
(покупатели с одинаковым приходом идут в порядке ввода).

**2. Случайный поток:**
`python queue_sim.py [--cashiers N] [--max-queue N|none] --seed S [--minutes M] [--interval I] [--service МИН-МАКС]`

Покупатели генерируются: магазин работает `M` минут (по умолчанию 720, это же время закрытия),
средний интервал между приходами `I` минут (по умолчанию 0.5, пуассоновский поток), время обслуживания - равномерно от МИН до МАКС (по умолчанию `2-5`).
Генератор - свой, с зерном `S` (`random.Random(S)`), глобальный `random` не трогать: одинаковые параметры → одинаковый отчёт.
Стандартный ввод в этом режиме не читается.

Общие параметры: `--cashiers` - число кассиров, целое ≥ 0 (по умолчанию 3);
`--max-queue` - сколько человек может стоять в очереди, целое ≥ 0 или `none` - без ограничения
(по умолчанию 10); `--close` - время закрытия (только в режиме 1; по умолчанию закрытия нет).

**Вывод** (stdout, код 0) - ровно в таком виде:
```
Результаты симуляции:

Общая статистика:
  Всего пришло покупателей: 6
  Обслужено покупателей: 5
  Ушло из-за длинной очереди: 1

Время ожидания:
  Среднее время ожидания: 1.3 мин
  Максимальное время ожидания: 3.0 мин
  Минимальное время ожидания: 0.0 мин

Очередь:
  Максимальная длина очереди: 2 человека
  Среднее время обслуживания: 3.2 мин на покупателя

Загрузка кассиров:
  Кассир 1: обслужил 3 покупателей, загрузка 100%
  Кассир 2: обслужил 2 покупателей, загрузка 60%
```
- В режиме 2 первая строка - с зерном из `--seed`: `Результаты симуляции (семя: 42):`.
- Минуты - с одним знаком после точки, загрузка - целые проценты; округление как у f-строки
  (`f"{x:.1f}"`, `f"{x:.0f}"`). Числа от 1000 - с пробелом между разрядами (`1 442`).
- Слова: `1 человек`, `2 человека`, `5 человек`; `обслужил 1 покупателя`, `2 покупателей`, `21 покупателя`.
- Если покупателей нет - все времена `0.0`; если кассиров нет - вместо списка строка `  кассиров нет`.
- Ожидание - от прихода до начала обслуживания; «ушедшие» в ожидание не входят. Загрузка кассира -
  его суммарное время обслуживания / продолжительность работы, где продолжительность - наибольшее
  из времени закрытия и момента, когда обслужен последний покупатель (если 0 - загрузка 0%).

## Договорённости
- В один момент сначала освобождаются кассы, потом приходит покупатель.
- Пришедший покупатель идёт к свободной кассе с наименьшим номером. Если свободных нет - встаёт в
  общую очередь (FIFO); если в очереди уже `--max-queue` человек (или кассиров 0) - уходит.
- Когда касса освобождается, к ней идёт первый из очереди; если в один момент освобождаются
  несколько касс, первый из очереди идёт к кассе с наименьшим номером.
- После закрытия (`приход >= время закрытия`) никого не впускают - такие покупатели вообще не
  считаются пришедшими, но тех, кто уже внутри, обслуживают.
- Сотни тысяч покупателей моделируются за секунды.

## Пример
`python queue_sim.py --cashiers 2 --max-queue 2 --close 10` с вводом:
```
0 3
1 4
1.5 2
2 5
2.5 1
3 2
```
выводит отчёт, показанный выше. Режим из условия: `python queue_sim.py --seed 42` (12 часов, 3 кассира,
обслуживание 2–5 минут, покупатель в среднем каждые 30 секунд, очередь не длиннее 10 человек).

## Git-сценарий (перенос одного коммита)
Всё делается в общем репозитории курса, в ваших ветках и тегах: вместо `<логин>` - ваш логин в edu.susu.
Ваша «главная» ветка - `<логин>/main`; если её ещё нет, создайте от `main`: `git switch -c <логин>/main main`.
Ветки и теги отправляйте в репозиторий: `git push origin <ветка> <тег>…`. Не удаляйте ветки, которые нужны для проверки.

1. Создайте черновую ветку: `git switch -c <логин>/t04-draft <логин>/main` и сделайте в ней **не меньше
   трёх** коммитов. Один из них - отдельное важное исправление ошибки в расчёте статистики, остальные -
   сырой код, который в главную ветку пока нельзя.
2. Перенесите в `<логин>/main` **только** исправление: `git switch <логин>/main` и
   `git cherry-pick -x <sha исправления>` (`-x` добавит в сообщение ссылку на исходный коммит).
3. Черновую ветку в главную **не сливайте**. Отправьте обе ветки.

Что проверяется: в `<логин>/t04-draft` не меньше трёх коммитов; ни один из них не попал в
`<логин>/main` слиянием; в `<логин>/main` перенесён ровно один коммит черновика (с тем же
изменением); ссылка `cherry picked from commit` - плюс.
